   - "project": the project's own code — a fix ticket in the project's own ticket system, but only for a failure on the latest master.    - "environment": where the work runs — the ticket's VM or worktree, its dependencies, the project's containers, its checkouts, caches, generated files, recorded test commands, the operator's machine (credentials, a shared checkout) — repaired in place where that is allowed, else by the operator.
   - "dependency": no fault at all — the block only waits for one of the ticket's own merge requests to merge: another of its merge requests depends on it, in another repository, and needs what it publishes only once merged (an image, a package, a digest pinned to it). Check it in `{agent-sh} ticket:merge-request-plan {project} {ticket} {variation}`: the one waited on is not Merged or Closed, and another of the ticket's merge requests lists it in depends-on.    - "rate-limit": no fault of the ticket's — Claude usage or rate limits stopped its agents (HTTP 429, "usage limit reached", "rate limit", an agent that died at 0 tokens on a limit). The harness resumes it on the project's API key fallback at once when it can, else waits for the limit to reset, not the operator.
   - "credentials": a missing or failing credential — a keychain item, a token, a login (gh, glab, gcloud, Claude) — not the project's code or the work's environment. A credential that is valid but the VM is not set up to use it — an undeclared registry mapping (pnpm or npm 401 on a scope with no /run/harness/npmrc entry), a missing gitconfig entry — is no credentials issue: "vm".

Repair Image fixes it on the Mac, one golden rebuild at a time; a missing or expired credential is never an image issue. Only what cannot be fixed in the ticket's VM is "image" (the ticket waits for the rebuild): the Lima template (cpus, memory, disk), kernel settings, the image's build itself, the registry; a missing tool or package is "vm".
   - "vm": a problem in the ticket's VM that can be fixed in place there and that every VM made the same way would have — a tool or package missing from the golden image (claude, bats), a cache or pulled container image it should carry, a file the harness writes into each VM as it starts (/run/harness/npmrc, gitconfig, env) missing an entry because its declaration lacks it, the credential itself valid. Repair the VM fixes it in this VM at once and the same change in its source (the image definition, or the VM-setup declaration) for later VMs, the ticket not waiting for any rebuild.
